# BrowseMemory Phase 1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a Chrome MV3 extension that captures readable browsing activity, stores and indexes it locally, supports offline BM25 search, and answers one source-grounded question through an OpenAI-compatible API.

**Architecture:** WXT owns the Chrome extension entrypoints while framework-independent TypeScript modules own capture policy, IndexedDB persistence, BM25, encryption, and RAG. The background service worker is the integration boundary; React side-panel and options UIs communicate with it through typed runtime messages.

**Tech Stack:** WXT, React 18, TypeScript, Tailwind CSS, Radix UI primitives, Lucide React, Dexie, Mozilla Readability, Vitest, Testing Library, fake-indexeddb, ESLint.

---

## File Map

- `package.json`, `wxt.config.ts`, `tsconfig.json`, `vitest.config.ts`: build and test configuration.
- `entrypoints/background.ts`: service-worker event orchestration.
- `entrypoints/content.ts`: Readability extraction and SPA change reporting.
- `entrypoints/sidepanel/`: compact Memory/Conversation React UI.
- `entrypoints/options/`: API, capture, storage, and privacy settings UI.
- `src/shared/`: domain types, constants, URL policy, and message contracts.
- `src/storage/`: Dexie schema and transactional repositories.
- `src/search/`: tokenization, BM25 scoring, and snippets.
- `src/capture/`: reading-session state machine and persistence coordinator.
- `src/ai/`: context assembly, OpenAI-compatible transport, and citations.
- `src/security/`: AES-GCM secret storage.
- `src/background/`: message handlers and application services.
- `src/ui/`: visual tokens and reusable compact controls.
- `tests/`: unit, component, and integration tests mirroring source ownership.
